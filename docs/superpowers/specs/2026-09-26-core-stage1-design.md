# 設計書：コア基盤＋1面（サブプロジェクト①）

作成日: 2026-09-26
元資料: `docs/concept.md`（協力防衛シューティング コンセプト書）

## 1. スコープ

全体を4つのサブプロジェクトに分割し、本書は①のみを扱う。

1. **コア基盤＋1面**（本書）
2. パワーアップ・ステージ進行・セーブ
3. 2〜7面の敵とボス
4. エンドレス2種・日記

### ①に含むもの
- 画面（仮想座標1000×1000、レターボックス、縦横両対応）
- 入力（PC：キー旋回＋マウス発射、スマホ：矢印ボタン旋回＋タップ発射）
- 視界・旋回・射撃・残機・無敵時間
- 雑魚敵：隕石、偵察ドローン
- ボスA（初期型）
- シーン：タイトル／プレイ中／ポーズ／結果
- 効果音（WebAudio合成）、音量・ミュート設定とその保存

### ①に含まないもの
- パワーアップ、ステージ選択と解放、ハイスコア以外のセーブ、BGM楽曲（再生の仕組みのみ用意）、日記、エンドレス、2面以降の敵

## 2. 技術方針

- 素のJavaScript、ES Modules、ビルド不要。GitHub Pagesにそのまま配置する
- Canvas 2Dでゲーム画面を描き、メニューとHUDはDOMのオーバーレイで作る
- ローカルで確認するときは簡易HTTPサーバーを使う（ES Modulesは `file://` では動かないため）
- 機械チェック：`node tools/check.mjs`（全jsに `node --check`）、`node --test`（ロジックの単体テスト）
- キャラクター・敵のビジュアルは図形ベースのデフォルメで、canvasのパスで描く。**AI生成の画像・動画は使わない**
- 前作「星降る夜をこえて」から以下を移植する：
  - `tone()` による効果音の合成、`initAudio()`、音量の仕組み
  - 音量スライダーとミュート
  - `--app-height` によるiOS対策、画面回転時の遅延resize、dprの上限2
  - パーティクル、`lerpColor`、`lightenColor`、重み付き抽選
  - CSS変数、配色、`.btn`、`.overlay`

### モジュールのルール
- `js/game/` はcanvasとDOMに触れない（純粋なロジックにする）
- ゲームの状態は1つの `state` オブジェクトにまとめ、引数で渡す。モジュールをまたぐグローバル変数は使わない
- シーンのインターフェースは `{ enter(ctx), exit(), update(dt), render(g) }`。切り替えは `setScene(name)` の1か所からだけ行う

## 4. 座標系と視界

### 世界座標（極座標）
- 敵・弾は `{ angle, dist }` で管理する。単位は度。angle=0が正面、+が右
- 自機の向きは `heading`。範囲は-90〜+90度で、この範囲に押し込める（後方は向けない）
- 敵の出現角度も-90〜+90度

### 画面座標
- 仮想キャンバスは1000×1000。自機は中心(500, 500)に固定
- 相対角 `rel = angle - heading`
- `|rel| <= FOV/2`（35度）の敵だけを描画し、判定の対象にする
- 画面上の角度 `φ = rel × (90 / 35)`（約2.57倍に広げる）。向いている方向が常に画面の真上になる
- 画面半径 `R = dist`（世界の距離は、そのまま画面上の中心からの距離として扱う）
- `x = 500 + R·sin φ`、`y = 500 − R·cos φ`
- 世界の最大距離（出現位置）は460。視界の扇形は画面の上半分を占め、下半分はUIの余白になる
- 逆変換：タップした画面座標 → φ → `rel = φ × 35/90` → 世界の角度 `heading + rel`。扇形の外（下半分）をタップしたときは、φを±90度に押し込めてから変換する

### 当たり判定
- 判定の瞬間の `heading` を使って、両者を画面座標に変換し、円同士で判定する（見た目と一致させるため）
- 視界外にいるものは当たらない
- 当たり判定の半径は、描画サイズの65%にする

### レターボックス
- 実際の画面の短い辺に合わせて、1000×1000の正方形を中央に配置する
- `scale = min(W, H) / 1000`
- 余った部分（横長なら左右、縦長なら上下）にはHUDとスマホの操作ボタンを置く
- dprの上限は2
- ポインターの座標は `(clientX − offsetX) / scale` で仮想座標に変換する

## 6. 操作

| 環境 | 旋回 | 発射 |
| --- | --- | --- |
| PC（ソロ／2人協力） | A/D、←/→ | マウスで狙ってクリック、押し続けると秒間4発 |
| スマホ | 画面下の左右ボタン（押し続けて旋回） | 扇形の中をタップ、押し続けると連射。指を動かすと狙いも追従する |

- PCのソロと2人協力は同じ処理。違うのはタイトル画面の案内表示だけ
- ポインターは `pointerId` ごとに追跡し、矢印ボタンの指と発射の指を同時に使えるようにする
- イベントは pointer 系だけを使う（前作の `bindTap` は4種類のイベントを重ねていたが、それはしない）
- Esc/Pでポーズ。タブが非表示になったら自動でポーズする
- 最初の操作で、オーディオを有効化する

## 7. ループとシーン

- `requestAnimationFrame` のループを常に1本だけ動かす。`dt = min(経過秒, 0.05)`
- シーン：`title` → `play` ⇄ `pause` → `result` → `play` または `title`

### play.update(dt) の順序
1. 旋回と発射（クールダウンを管理）
2. 出現表の処理
3. 敵とボスの動き
4. 弾の移動、画面外や範囲外に出た弾の削除
5. 判定：自弾と敵・敵弾・ボス
6. 中心への到達：敵・敵弾が `dist <= HIT_RADIUS_CORE` になったら被弾（無敵中は、到達したものを消すだけ）
7. エフェクト
8. 終了判定：ボス撃破 → クリア、残機0 → ゲームオーバー

被弾時は、残機-1、無敵1.5秒（自機を点滅させる）、ノックバック（KNOCKBACK_RADIUSより内側の敵・敵弾の `dist += KNOCKBACK_DIST`）を行う。

## 8. 敵の定義

```js

```

| 敵 | HP | 動き |
| --- | --- | --- |
| meteor（隕石） | 1 | 中心へ直進。速度は 460 / (10 × (1±0.15)) |
| drone（偵察ドローン） | 2 | 距離300〜380の目標地点まで接近 → ホバリング（角度±4度を正弦波で揺れる）＋3.5秒ごとに敵弾を撃つ → 15秒経ったら直進で接近を再開 |
| enemyShot（敵弾） | 1 | 撃ち落とせる。秒速120で中心へ |
| bossMinion（子機） | 1 | 直進。約5秒で到達 |

## 9. 1面の出現表（stage1.js）

| 区間 | 隕石の間隔 | ドローンの間隔 |
| --- | --- | --- |
| 0〜20秒 | 3.0秒 | なし |
| 20〜60秒 | 2.0秒 | 8秒 |
| 60〜90秒 | 1.5秒 | 6秒 |

90秒が過ぎたら出現を止める。雑魚がいなくなったらボスAが出る。

## 10. ボスA（初期型）

- HP40、半径（描画）60、距離380、角度は-60〜+60度をゆっくり往復する（10度/秒）
- 仮想エリア下部（y=780付近）にHPバーを出す（視界外にいても表示する）。上部は正面の敵の出現位置と重なるため避ける
- **分散召喚**：6秒ごと。互いに20度以上離れた3方向から子機を出す
- **直進弾**：4秒ごと。敵弾を0.25秒間隔で3連射する
- **突進**：12秒ごとに距離を−40する（下限200）
- パラメータ（召喚数、各間隔）はデータで持ち、強化型ではこれを上書きする

## 11. スコアと結果

- 隕石100、ドローン200、子機50、敵弾10、ボス5000
- 撃破数（敵弾は含めない）を記録する
- 結果画面には、クリア／ゲームオーバー、スコア、撃破数、ハイスコアを表示する。ボタンは「もう一度」と「タイトルへ」
- ①ではコンティニュー＝1面の最初からやり直し

## 12. セーブ

- キー `td_save_v1` に `{ version: 1, settings: { muted, bgmVol, seVol }, highScore }` を保存する
- 読み書きはtry/catchで囲み、失敗したら既定値で動かす

## 13. 描画

- 背景：星空（前作から移植）
- 視界：扇形を薄く明るくし、その外側を暗くする。扇形の境界線を描く
- 自機：丸い体、回転する砲身（常に真上を向く）、ほっぺ。被弾後の無敵中は点滅
- 隕石：ごつごつした多角形、ゆっくり回転
- ドローン：円盤＋目＋小さなプロペラ
- 子機：小さなドローン
- ボスA：大きな母艦の円盤
- 敵弾：光る小さな玉
- 自弾：光る線
- HUD：残機、スコア、経過時間（DOM）
- 向きゲージ：自機の下に、旋回範囲180度の弧と、現在の視界70度の範囲を示す（視界外の敵の情報は出さない）

## 14. テスト

`node --test` でロジックを確認する。
- `view`：世界⇔画面の変換（往復で元に戻る、視界の境界、扇形の外をタップしたときの押し込み）
- `turret`：旋回の制限、発射のクールダウン、無敵時間
- `collision`：視界外は当たらない、画面座標の円判定、被弾とノックバック
- `spawner`：区間ごとの出現数、90秒で止まる、ボスが出る条件
- `boss`：召喚の方向が20度以上離れている、突進の下限

描画と入力はブラウザで目視確認する（PCの横長、スマホの縦長の両方）。
